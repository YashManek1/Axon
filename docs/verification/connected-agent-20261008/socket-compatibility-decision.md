## Required implementation contract

1. **Keep the launch request literal.** Extract only the existing agent-launch argument construction/invocation as needed into a shared, injected-call helper. Its production path must build and send the exact literal socket bind `/var/run/docker.sock:/var/run/docker.sock`; do not accept a source-path option, environment override or diagnostic-derived value. Tests must capture the actual argv delivered to the injected Docker adapter. Do not dump the full argv/env file into evidence.
2. **Record intent separately from inspection.** Before invocation, save a small allowlisted socket intent derived from those same validated argv, tied to the run and planned agent name. After successful creation, use the already recorded exact attempted container ID to correlate it with inspection. A missing/mismatched run/name/attempted ID or missing/nonliteral intent fails closed. A hand-written parallel expected value is not proof that the literal argument was sent. Preserve attempted-resource recording before mutation and existing recovery on launch failure.
3. **Exactly two accepted representations.** The default remains source `/var/run/docker.sock`. The only additional source is the complete literal `/run/host-services/docker.proxy.sock`, with bind type and destination exactly `/var/run/docker.sock`. No regex, suffix match, normalization, symlink resolution, source discovery or learned allowlist. For both branches require exactly the expected two observed mounts and exactly two corresponding observed Binds: the named journal bind string plus the selected socket-source/destination string, order-independent. Missing/malformed/extra/inconsistent Binds or mounts reject. Keep the exact named journal/type/destination guard.
4. **Restrict the proxy branch to the designated local Desktop endpoint.** Require the actual selected context to be exactly `desktop-linux`, its inspected endpoint to be exactly `npipe:////./pipe/dockerDesktopLinuxEngine`, and the preflight daemon to have nonempty ID and Linux OSType. Compare raw endpoint equality, not its scheme alone. Capture only bounded allowlisted context/endpoint/OS/daemon evidence. These are local compatibility assertions, not authentication against a malicious local administrator. This contract does not assert that the endpoint was already recorded by r8 (only its `npipe` scheme was); if the exact endpoint differs, stop and return the observation for decision, do not add variants. No new public/remote endpoint is authorized.
5. **Preserve all other barriers and ordering.** Ownership/run/name/exact attempted ID precede trusted diagnostic capture. Existing nonprivileged, single-network and no-published-port checks remain. Mount representation passes before any daemon exec; same-daemon comparison against the preflight ID remains mandatory before verifier invocation, using the immutable agent ID. Runner validation/copy/exec isolation, nested cleanup, owned cleanup and all twelve resource boundaries remain unchanged.
6. **Keep reporting truthful and safe.** Rename diagnostic `requestedBinds` to `observedBinds` (including malformed/truncated field labels); they are daemon-inspected values. Add only bounded/redacted launch-intent and selected representation/context evidence needed to distinguish request from observation. Keep complete known-secret redaction before bounds, fixed-field flags, failure diagnostic retention, cleanup, final serialization and nonzero behavior on the existing shared production path. No raw context/config/env export. Never say same-daemon is verified until its actual query passes.

A context name alone is insufficient. Reject remote npipe host, TCP/SSH/Unix proxy cases and malformed metadata. The default literal branch must not silently switch to proxy.

Assert no daemon/verifier call on rejection, retained safe owned diagnostics, cleanup, persisted nonzero report. Identity failure still yields no trusted diagnostic.
- On accepted proxy topology, a different daemon must still suppress verification; only matched daemon advances. Keep all r8 redaction, clipping, malformed input, failure/cleanup/report tests. Include secrets in any newly allowed dynamic field. Reuse unchanged runner/cleanup evidence rather than duplicating implementation.
- Run the focused two-file offline guard suite and syntax checks, record native status/counts/no skips, freeze all ten harness hashes, then independent security review. Only a subsequent explicit GO permits **one** fresh isolated full harness. Runtime acceptance still needs real success/exit-7 failure, persisted approval/target/attempt correlation, replay/saved GET, native exit 0, nested cleanup and all twelve owned resources absent.

## Ownership, rejected alternatives and risks

Allowed implementation writes: `scripts/codex/approval-connected-agent-lib.mjs`, `scripts/codex/approval-connected-agent-orchestrator.mjs`, `scripts/codex/approval-connected-agent.guard.test.mjs`, and bounded verification/tracker records owned by Sol. No Compose, runner, fixture, verifier, product backend/Rust or cleanup-authority changes. Reviewer wrote only this decision file; other edits remain owned by their authors.

Rejected: accepting the observed source automatically, global proxy acceptance, trusting rewritten Binds as request proof, removing the same-daemon check, or substituting another Docker probe for offline guard evidence. Socket access still grants substantial local daemon authority; fixed metadata does not defeat a compromised host. Unknown proxy representations must fail closed.

A separately authorized direct-host Linux test environment could retain the literal socket representation, but no such ready isolated environment is evidenced here and the harness currently pins `desktop-linux`. Moving hosts/context is a larger scope, not an automatic safety improvement or the required next step. This local compatibility slice makes no Linux-fleet or deployment claim.
